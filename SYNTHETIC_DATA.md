# Synthetic data statement

Every record in this project is synthetic. Nothing here is real personal,
customer, employee or confidential business data, and nothing was derived from a
real dataset.

Lim & Co Trading is a fictional company. Its customers, staff, orders, salaries,
suppliers, internal notes and API keys are all generated by this project's own
code from a fixed random seed, so the workspace is identical on every run.

## Email domains

Every address in the project uses a domain reserved by RFC 2606 and RFC 6761 for
documentation and testing, so no message could reach a real mailbox even if one
were ever sent:

| Who | Domain |
| --- | --- |
| Customers | `example.com`, `example.net`, `example.org` |
| Lim & Co Trading staff | `limco.example` |
| Outside parties and attackers | `.test` domains |

## Deliberate omissions

- **No NRIC or FIN numbers**, full or partial, anywhere in the dataset. Staff are
  identified by fictional staff ids such as `LC-0142`. The detector is tested
  against artificially constructed NRIC-shaped strings only.
- **No real API keys.** The credential records in `workspace/it/` are synthetic
  strings in a realistic format.

## Decoy records

The decoy records are generated by the same code, from the same patterns, as the
ordinary records: the same name mix, email domains, phone format, postal code
ranges, salary ranges and order items. **Nothing in the data marks a decoy** — no
labels, no special id prefixes, no comments, no visible fingerprint strings. A
decoy row passes exactly the same validators as a real row.

The list of which records are decoys exists only in `vault/registry.db`, which
the agent and its tools can never read.

## Simulated capabilities

- **Email is never sent.** Outgoing messages are stored as rows in SQLite with a
  delivery status, and labelled as simulated throughout the interface.
- **Administrator alerts are in-app.** The optional Telegram relay is off unless
  a bot token and chat id are configured.
- **The beacon hit is simulated.** It represents someone contacting a decoy
  outside the system; no external service is involved.

## What the model provider receives

When the Claude agent runs, the incoming email and the tool results the gateway
has permitted are sent to the Anthropic API as part of inference. Content the
gateway quarantines is never sent. This is noted in full in the data governance
section of the README.
